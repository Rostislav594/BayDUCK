# BuyDUCK

## Подтверждённые требования

- Название магазина: **BuyDUCK** (переименован из BayDUCK по запросу пользователя 2026-10-23).
- Интернет-магазин преимущественно обуви, а также одежды и аксессуаров.
- Рынок: Украина.
- Язык по умолчанию: украинский (`uk`).
- Дополнительные языки: русский (`ru`) и английский (`en`).
- Необходим переключатель языков. Локализацию учитывать с начала разработки: тексты интерфейса хранить отдельно от компонентов, предусмотреть переводы контента товаров.
- Валюта витрины: гривна (`UAH`), исходя из рынка Украины.
- Сайт делается для клиента, который уже продаёт на OLX (Украина). Нужна двусторонняя связь с **его собственным** аккаунтом OLX: импорт объявлений в каталог BuyDUCK и публикация/изменение объявлений на OLX с сайта (подтверждено пользователем 2026-10-21).
- Сайт связан только с OLX (другие маркетплейсы, скорее всего, не нужны). Заказ возможен двумя способами: **доставка Новою Поштою** с оформлением на сайте и **«Безпечна угода» OLX** — покупка на странице объявления OLX (уточнено пользователем 2026-10-28). Сценарий и решения клиента — `docs/ordering-flow.md`.

## Стратегия разработки и хостинг (решение от 2026-10-27)

- **Сейчас делаем кликабельный прототип.** Все функции, которым нужен сервер (личный кабинет и вход, заказы, оплата, доставка, статистика, OLX), реализуются как работающие в браузере демо: данные хранятся в `localStorage`, внешние сервисы не подключаются. Интерфейс и сценарии должны выглядеть и вести себя как в настоящем магазине.
- **Позже будет сервер на Railway.** К нему подключаются все необходимые внешние сервисы: база данных, настоящая авторизация, отправка писем, оплата, доставка, аналитика, OLX Partner API.
- Демо-логику держать отдельными модулями с понятной точкой замены на вызовы сервера (как `track()` в `src/analytics.js` и хранилище аккаунтов в `src/accounts.js`).
- Не предлагать заново выбор между Supabase, собственным сервером и демо-режимом: решение принято. Вопрос возвращается, только когда пользователь скажет, что пора подключать Railway.
- Вход в личный кабинет — по почте и паролю. Быстрая покупка без регистрации обязательно остаётся.

**Личный кабинет (2026-10-27):** сделан как демо в браузере (`src/accounts.js`, страница `#account`, диалог входа). Регистрация, вход, «Запомнить меня», восстановление пароля (экран без отправки писем), смена пароля, профиль с данными доставки, история заказов и удаление аккаунта. Гостевая быстрая покупка не изменилась и ничего личного не сохраняет. При переходе на Railway нужно заменить хранилище на API сервера, добавить подтверждение почты и реальную отправку писем для сброса пароля.

## Интеграция с OLX

Способ — официальный OLX Partner API. Сбор данных со страниц OLX без API не используем: это нарушает правила OLX, ненадёжно и грозит блокировкой аккаунта клиента.

Что известно на 2026-10-21 (по [FAQ OLX Developer Hub](https://developer.olxgroup.com/faq) и открытым SDK; подробная документация открывается только после одобрения):

- API бесплатный; платными остаются сами объявления по тарифам OLX.
- Доступ выдаётся по модерируемой заявке; ориентирован на бизнес со своей системой учёта товаров (CRM). Заявки «для пробы», от студентов или с неточными данными отклоняются.
- Авторизация OAuth: клиент разрешает приложению доступ к своему аккаунту. Доступны только объявления авторизовавшего пользователя: список, просмотр, создание, изменение, снятие и активация. Данные других продавцов и рынка недоступны.
- Нужно сопоставить категории и обязательные атрибуты OLX (для обуви — размер, бренд, состояние и т. п.) с категориями BuyDUCK.

Последствия для архитектуры: интеграции нужен backend — секрет приложения нельзя держать во фронтенде, токены клиента нужно хранить и обновлять, импортированные товары — хранить в базе, а для клиента нужна закрытая панель управления. Статический прототип на GitHub Pages для этого недостаточен; хостинг и база выбираются на этом этапе.

Порядок работ: заявка на доступ от имени бизнеса клиента (черновик — `docs/olx-partner-api-application.md`) → после одобрения проверить фактические эндпоинты и лимиты по документации → backend и импорт объявлений → публикация с сайта.

**Предварительное решение (2026-10-21):** начинаем без API — с варианта В, ручной связки. Каталог ведётся в панели BuyDUCK, сайт готовит текст и фото для объявления на OLX, в карточке товара есть кнопка «Купити на OLX». Описание сценариев, данных и открытых вопросов — `docs/olx-manual-flow.md`. Заявка на API остаётся возможным следующим шагом; посредники вроде ApiX-Drive рассматривались как план Б.

**Админ-панель (2026-10-26):** отдельная страница `admin.html` на существующем локальном сервере (`/admin`), без ссылки с витрины и без входа через авторизацию на сайте. Пока это заглушка: товары только для чтения из демо-каталога, раздел OLX ждёт ключей API. Для Shafa открытого API нет, поэтому реализован вариант с готовым шаблоном объявления: продавец выбирает товар, размер, раздел, состояние и цену и копирует готовые поля в форму Shafa. Тексты объявления всегда на украинском, без ссылок и контактов. Комиссия Shafa по договору-оферте — 9–20 % с продажи, не более 500 грн.

**Заказ (2026-10-28):** реализован как демо в браузере. Витрина: в карточке товара кнопки «Додати в кошик» и «Купити з Безпечною угодою OLX»; в корзине выбор «Нова Пошта» или «Безпечна угода OLX» (список товаров со ссылками на объявления). Форма Нової Пошти: прізвище, ім'я, телефон (+380), місто с подсказками, відділення або поштомат и номер, оплата післяплатою или передоплатою на карту, подтверждение в Viber или Telegram, комментарий. Доставку оплачивает получатель. Гость не получает профиль, его данные для отправки хранятся только в заказе; после заказа корзина очищается. Заказы хранятся в `src/orders.js` (`buyduck:orders`) — точка замены на API сервера. В админке вкладка «Замовлення»: все заказы, фильтр по статусам (Нове, Підтверджено, Очікує оплату, Відправлено, Отримано, Скасовано, Повернення), кнопки Viber/Telegram, ввод ТТН с проверкой 14 цифр и ссылкой на отслеживание НП, напоминание снять товар с OLX. Статус и ТТН видны покупателю в личном кабинете. Ссылок на настоящие объявления OLX у демо-товаров нет (`olxUrl` не задан) — кнопка показывает пояснение. Переходы на OLX учитываются во вкладке «Активність».

**Активность посетителей (2026-10-26):** в админке есть вкладка «Активність» — посещения, просмотры, корзина, оформления, демо-заказы, сумма, конверсия, график по дням, воронка, популярные товары и поисковые запросы. Пока события хранятся только в браузере посетителя, поэтому админка видит лишь действия в своём браузере. Для реальной статистики по всем посетителям нужно выбрать сервер или сервис аналитики (решение не принято); точка замены — `track()` в `src/analytics.js`.

## Визуальное направление

**Раскладка первого экрана (2026-10-26):** владелец расставил карточки и мультяшную одежду вручную в редакторе `/?edit-layout` на экране 1912 px; это одобренная раскладка для desktop от 1280 px. Исходные координаты — `artifacts/hero-layout.json` (локально, вне git); CSS — блоки «Owner-approved desktop layout» в `src/styles.css` и `src/playful-clothes.css`. Для новых правок композиции сначала предлагать тот же редактор.

С 2026-10-23 используется надпись **BuyDUCK**: `assets/branding/buyduck-wordmark-mascot-v3.png`. Встроенным image_gen заменена буква a на u с сохранением композиции и маскота на D. Предыдущие версии исходников сохранены. Название обновлено на главной, в каталоге, диалогах, подвале и трёх языковых словарях; прежние ключи localStorage сохранены для совместимости. Ниже остаётся история развития логотипа под прежним названием.

Основной ориентир — `DESIGN.md`: светлая основа, крупные фотографии товаров, округлые карточки, мягкие тени, фиолетовый акцент `#5433eb`.

Фирменный персонаж: утка в кроссовках, кепке задом наперёд и клетчатой рубашке.

Первый концепт персонажа: `assets/branding/bayduck-mascot-concept-v1.png`. Пользователю понравился маскот; его внешний вид сохраняем при дальнейшей разработке.

По уточнению пользователя главный акцент логотипа — надпись **BuyDUCK**. Утка сидит на букве **D**, сохраняя объём, полную фигуру, одежду и заметные кроссовки.

Второй концепт: `assets/branding/bayduck-wordmark-mascot-v2.png` — крупная надпись и сидящий на D персонаж, PNG с прозрачным фоном. Концепт ожидает обратной связи; компактная версия знака ещё не разработана.

На главной логотип перенесён из левого угла шапки в центр первого экрана над поиском, заменив слоган и описание. В каталоге компактный логотип в шапке сохранён как переход на главную.

На desktop основной контейнер имеет симметричные боковые отступы по 68px: левый отступ резервирует место для навигационной панели, правый сохраняет центрирование сайта относительно окна. На мобильных экранах оба отступа убираются вместе с панелью.

Надпись BuyDUCK с маскотом центрируется относительно поисковой строки без учёта боковой корзины: ряд сдвинут влево на половину доли корзины. На телефонах ширина ограничена, чтобы корзина оставалась внутри экрана. На 901–1100px размер композиции адаптирован под левую карточку товара; на 781–900px декоративные карточки скрываются. После исчезновения корзины положение надписи сохраняется.

По отдельному запросу пользователя в свободные места первого экрана добавлены мультяшные элементы одежды в стиле маскота. Текущий набор: два отдельных кроссовка (массивный низкий и высокий баскетбольный), портфель и две дополнительные пары — песочно-терракотовая и мятно-серая. Новые пары используют sand-pair-v1.png и mint-pair-v1.png; каждая пара является одним интерактивным предметом с общей анимацией. Худи и носки заменены кроссовками по последнему запросу пользователя; прежние иллюстрации сохранены. Низкий кроссовок использует sneaker-v1.png, высокий — новый high-top-v1.png; портфель не изменён. По нажатию любой предмет летит в нарисованную корзину перед B: корзина делает полный оборот, поворачивается ручкой вверх, принимает предмет и возвращается в исходное положение. После попадания предмет остаётся скрытым до обновления страницы, перехода на другую страницу магазина или переключения вкладки браузера. Смена языка, прокрутка и изменение размера окна его не возвращают. Состояние собранных иллюстраций хранится только в памяти текущего просмотра. Когда собраны все пять предметов, подсказка скрывается. После прежней подсветки, секундной паузы и возврата на бок корзина за 900ms плавно въезжает вправо за букву B и скрывается. Надпись не смещается, место корзины в разметке сохраняется. Финальное состояние переживает смену языка, прокрутку и изменение размера окна; обновление страницы, переход между страницами магазина или переключение вкладки возвращают всю сцену. Для уменьшенного движения финал заменён затуханием прозрачности за 180ms. Быстрые нажатия на разные предметы ставятся в очередь; повторное нажатие на уже летящий или ожидающий предмет не дублирует полёт. Прежние индивидуальные анимации и звёздочки удалены. Постоянного движения нет. Это согласованное расширение исходного `DESIGN.md`, в котором иллюстрации не предполагались. Песочно-терракотовая пара закреплена в левом верхнем углу первого экрана, мятно-серая — в левом нижнем. Портфель возвращён на прежнее место справа вверху, отдельные кроссовки находятся ниже категорий. Размеры и зазоры адаптированы для сохранения проходов полёта. Поддержаны клавиатура, три языка и `prefers-reduced-motion` (короткая смена прозрачности вместо полёта и вращения). При перерисовке интерфейса, прокрутке, изменении размера окна или предпочтения движения незавершённая анимация отменяется; предмет, уже попавший в корзину, остаётся скрытым, а ещё не долетевший восстанавливается. Это декоративное взаимодействие, которое не меняет товары в настоящей корзине магазина.

Перед буквой B главного логотипа добавлена повёрнутая корзина для покупок: днище слева, высота соответствует букве. Текущая версия — мультяшный PNG `assets/branding/shopping-basket-sideways-v3.png` в стиле худи и портфеля; предыдущий SVG и одобренный PNG надписи и маскота сохранены. Промпт лежит рядом с новой корзиной. Дублирующий блок «Каталог» в подвале удалён, помощь и основные переходы магазина сохранены.

По следующему комментарию худи перенесено ниже категорий, под «Усе» и немного левее этой кнопки; размещение адаптировано для desktop, планшетов и телефонов.

В версии корзины v3 ручка стала светлой, в цвет днища; фиолетовый обод сохранён. Корзина придвинута почти вплотную к B: дополнительный промежуток между изображениями убран.

Подача общей анимации уточнена: корзина вращается с постоянной угловой скоростью, без замедления между полным оборотом и положением ручкой вверх. Предметы летят по скруглённым маршрутам в обход видимых частей логотипа, поиска, категорий, карточек и других иллюстраций, после чего заходят в корзину строго сверху. Маршрут рассчитывается по текущей разметке. Все предметы движутся с одной скоростью 400 CSS px/s: длинный обход занимает больше времени. Исходный размер сохраняется на маршруте; уменьшение начинается только на последнем участке перед попаданием в корзину. Границы маршрута учитывают полный размер и наклон изображения. За ним тянется короткий затухающий синий хвост кометы (`#3185ff`). Синий используется только в этом запрошенном эффекте, без изменения основного фиолетового акцента интерфейса. Геометрия маршрута вынесена в `src/flight-path.js`; режим уменьшенного движения не создаёт хвост.

Последние уточнения подачи: вращение корзины начинается одновременно с полётом предмета, затем корзина ждёт его ручкой вверх. Размер хвоста пропорционален меньшей стороне изображения одежды: длина 65%, ширина основания 60%, с сужением к кончику. Хвост начинается позади предмета, повторяет изгибы пути и уменьшается вместе с предметом непосредственно перед попаданием в корзину. Портфель пересекает центральную область логотипа только над маскотом, без нижнего обхода. При попадании предмета обод кратко подсвечивается отдельным слоем поверх существующих пикселей обода; свечение гаснет за 300ms. После затухания корзина остаётся ручкой вверх ещё одну секунду, затем возвращается на бок. Остальные части корзины не подсвечиваются.

Исходные PNG и промпты генерации: `assets/playful/`. Разметка и анимации: `src/playful-clothes.js`; адаптивное размещение: `src/playful-clothes.css`.

## Текущее состояние

Десктоп от 2026-10-23 приведён к той же композиции, что и мобильная версия: логотип и поиск над категориями, три карточки разного размера и на разной высоте ниже, асимметричные интерактивные иллюстрации вокруг. На desktop базовая ширина карточки адаптируется от 156 до 196px; разница размеров и наклоны совпадают с мобильной версией. Карточки также видны в переходном диапазоне 781–900px. Общие стили карточек и иллюстраций используются для всех экранов; переменные размеров переименованы в `--hero-card-width` и `--hero-extra-row`. На 781–1000px категории компактнее, чтобы длинные переводы не пересекались с иллюстрациями. Прежние рукописные декоративные подписи скрыты, как на мобильной версии.

Проверки общей композиции: 19 тестов, сборка, `git diff --check`, 322 браузерные проверки полётов без ошибок JavaScript; 33 проверки отсутствия перекрытий на 11 ширинах 320–1920px и трёх языках; 9 проверок открытия карточек с клавиатуры на desktop. Кадры: `artifacts/shared-hero-621.png`, `artifacts/shared-hero-1024.png`, `artifacts/shared-hero-1440.png`.

Последнее уточнение от 2026-10-23: мобильные интерактивные кроссовки размещены асимметрично — мятная пара выше слева, низкий кроссовок сдвинут вправо и ниже, высокий расположен на другой высоте ближе к центру; изменены их наклоны и положение верхней терракотовой пары.
